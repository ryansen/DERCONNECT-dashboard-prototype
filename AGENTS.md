# Project instructions

Apply the user's global Karpathy coding guidelines alongside these project-specific rules.

## Explicit approval required before pushing or publishing

- Work locally by default. Implement changes and complete local verification before asking for approval of the finished result.
- Do not push any branch or tag, merge a pull request, trigger a remote deployment, publish a site, or change hosting settings until the user explicitly approves the finished changes as good to push or publish.
- Requests to change the dashboard, references to its live URL, and approval of earlier changes do not authorize pushing or publishing new changes.
- Approval applies only to the reviewed changes. If further changes are made, obtain fresh approval before pushing or publishing them.
- Show the user the local result and verification summary, then wait for their explicit approval. Do not treat silence as approval.
- This instruction-file update must remain local unless the user explicitly approves pushing it.
